# contract_tests

Black-box HTTP suite for the helmstudio public API (`contracts/openapi.yaml`): it talks only HTTP to `BASE_URL`
(Kong in front of the services) and never imports server code. It is the gate for every milestone.

The stack under test runs the **fake runner** (host `fake`, env `fake`, workflows `echo`, `echo-video`, `echo-image-to-video` and, from API 1.19, `echo-retake` and `echo-a2v`) and must be one you can
throw away: every run creates users, sessions and runs that it never deletes.

## Run

```sh
make -C contract_tests venv              # uv sync --frozen into .venv
make -C contract_tests check-contracts   # ../contracts: schemas, fixtures, openapi.yaml (no stack needed)
make -C contract_tests collect lint      # no stack needed

# against the test stack (helmstudio-test, Kong on 127.0.0.1:8390); `make test` from the repo root brings it up
# and runs this with a fresh key and the test admin
make -C contract_tests test CONTRACT_SCHEMAS=1 API_KEY=... ADMIN_EMAIL=admin@helm.test ADMIN_PASSWORD=...
make -C contract_tests test API_KEY=... ARGS="-k runs -x"   # any pytest args
```

| env | meaning |
|---|---|
| `BASE_URL` | the API root (default `http://127.0.0.1:8390`, the test stack; never the dev stack on 8300) |
| `API_KEY` | sent as `X-API-Key`: a client key (`auth apikey <client>`) |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | the stack's root admin; it creates users A and B on every run (there is no sign-up) |
| `CONTRACT_SCHEMAS=1` | validate every JSON response, and every SSE event, against `contracts/openapi.yaml` for its path, method and status; a route or status the spec doesn't list fails (`OPENAPI_PATH` overrides the location; see `tests/schemas.py`) |
| `JOB_TIMEOUT` | seconds to wait for a run or an event (default 60) |
| `COMPOSE_PROJECT`, `FAKE_OPENAI_URL` | how `test_director.py` reaches the fake OpenAI server: `docker exec <project>-fake-openai-1` (default `helmstudio-test`), or over HTTP at that URL |
| `SERVER_HOST`, `KEY_SECRET` | the host a fake local server shares (default `fake`, in `PIPELINES_SERVER_HOSTS`) and the placeholder key file a fake remote names (default `fake-openai`) |

## The fake OpenAI server

`fake_openai/server.py` (stdlib only; service `fake-openai` of `deploy/compose/fake.yml`, no host port) stands in for
every local server and remote provider (API 1.15): http on 8000, https on 8443 with a self-signed certificate it
writes to the `fakeai-certs` volume. `GET /v1/models`, `POST /v1/chat/completions` (answers the next response queued
for the model by `POST /__script`, else the prompt's `ECHO-TURN <n>:` / `ECHO-ANSWER:` script as `echo-ask` does,
as native tool_calls when the request has tools), `GET /__requests`, `POST /__reset`; `python server.py call METHOD
PATH [-]` makes one request from inside the container. Nothing real is ever called.

## The fake hub

`fake_hub/server.py` (stdlib only; service `fake-hub` of `deploy/compose/fake.yml`, no host port, the fake runner's
`HF_ENDPOINT`) stands in for the Hugging Face Hub (API 1.16): the revision, tree and paths-info API and
`/resolve/` with ETag / X-Repo-Commit / X-Linked-* headers and `Range` (206). Three repos back the echo pack's tiny
model (`runner_service/packs/echo`, model `echo`): `helm-test/echo-tiny` (variant tiny), `-plus` (two 12 MiB shards
at 1 MiB/s, so a cancel or a restart lands mid-download) and `-gated` (401 GatedRepo without the placeholder token),
all with the same vae bytes (shared by content hash). It writes the placeholder token file the runner reads
(`RUNNER_HF_TOKEN_FILE`, volume `hubsecrets`); `POST /__token {"present": bool}` removes or restores it,
`GET /__requests` lists the file GETs (`done`: fully sent), `GET /__manifest` the files' sizes and SHA-256,
`POST /__reset` clears the log. Tests reach it with `docker exec <project>-fake-hub-1 python server.py call …` and
read the runner's scratch models root (volume `fake-models` at `/models`) the same way. Nothing real is downloaded.

## Resilience

`resilience.sh` restarts studio, runner, nats, postgres and kong of the running helmstudio-test stack one at a time,
each in the middle of a ~12 s echo run, and requires that the run ends (succeeded, or failed/cancelled with an
error: never stuck queued or running) and that a new run afterwards succeeds. `studio-queued` restarts studio while a
second run is still queued behind the first, and requires that run to succeed. `batch-pipelines`, `batch-studio`,
`batch-nats`, `batch-postgres` restart that service in the middle of a 12-row slow echo batch and `batch-kill` SIGKILLs
the pipelines container and starts it again; the script presses Resume whenever the batch is paused, and the batch
must end `done` with exactly 12 runs (one per row) and 12 takes. `pipeline-parked` runs a 3-row echo pipeline with a
gate, picks row 1 and restarts pipelines and studio while its edit runs and rows 2 and 3 are parked, then resumes
and picks the rest: the batch must end `done` with exactly 6 runs and 6 distinct takes, one per row. `agents-parked` (API 1.14) runs a
3-row pipeline still → judge (Suggest, `echo-ask`) → out and restarts pipelines and studio once row 1 is parked on its
suggestion while the other rows make stills or wait on judge calls; after Resume and agreeing with every suggestion the
batch must end `done` with exactly 3 still runs, 3 judge runs and one decision per row (none asked twice). It takes a
few minutes. `director-mid` (API 1.15) restarts pipelines while the
director is mid-reply to a chat message asking for a row and a 3-shot fan-out is half done: after Resume the batch
must end `done` with exactly 2 rows (3 and 2 takes), 5 distinct shot runs and takes and one director reply.
`model-download` (API 1.16) restarts the fake runner and studio while the echo pack's plus variant downloads from the
fake hub: the job must end `succeeded` and every file on the runner's disk must have the hub's SHA-256.
`export-restart` (API 1.17) restarts the media runner (`EXPORT_RUNNER_SVC`, default `runner`) and studio while
ffmpeg exports 20 minutes of black at 1280x720: the job must end once (succeeded with exactly one export take, or
failed/cancelled with none and a new export accepted); SKIP when no env advertises `media`.
`batch-hostb` (API 1.18) starts the second fake host (profile `hosts`), SIGKILLs it while it runs a row of the
12-row batch and requires `done`, exactly 12 runs and 12 distinct takes and a row retried after the loss
(`lost_host`). `handover-studio` restarts studio while a run waits for another env of its host to unload and requires it to
start exactly once (attempt 1, one `running`); it needs a host with two envs that report memory and `HANDOVER_HOLD` /
`HANDOVER_WAIT` workflow ids, so it prints SKIP on the fake stack (one env, no memory).

```sh
make resilience   # from the repo root: brings the test stack up, makes a key, runs the script
API_KEY=... ADMIN_EMAIL=admin@helm.test ADMIN_PASSWORD=... contract_tests/resilience.sh [svc ...]   # test stack already up
```

Kong's sign-in rate limit is 20 a minute per IP; the suite signs in about that often, so a test may pause once for
`Retry-After`.
