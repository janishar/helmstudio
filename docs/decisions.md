# Decision log

Append-only. One line per decision: the date, the decision, and the reason. Never delete an entry — supersede it with a new one that says what it replaces.

Read it before starting on anything and add to it when you finish. Whatever is not written down here gets re-decided later, differently, by whoever picks the work up next — including you, six months from now.

## 2026-09-15 · design sprint frozen

- 2026-09-15 · daemon · **Go, stdlib-first, single binary on 127.0.0.1:8700** — matches h3c-studio and iris-studio; zero-install for users; subprocess supervision and reverse proxy are stdlib-shaped.
- 2026-09-15 · manifest · **`processes[]` replaces a single `run` block** — a studio is not always one server; an engine sidecar or a queue worker must be a data change, not a Go special case. `run:` survives as sugar for a single main process.
- 2026-09-15 · manifest · **manifest lives in the studio's own repo as `helmstudio.yaml`; the registry holds pointers** — two copies drift, one does not; a studio can announce a new build step without a helmstudio release.
- 2026-09-15 · manifest · **three resolution sources, first match wins: local file → in-repo → registry inline** — most repos will never ship a manifest, so anyone must be able to write one. A manifest is a description of a repo, not a file only its author can provide.
- 2026-09-15 · manifest · **`build[].shell` declared now, default `sh`** — a later Windows port must not invalidate every manifest ever written.
- 2026-09-15 · runtime · **`framework` and `backends` are separate fields** — PyTorch-on-cuda and PyTorch-on-mps are entirely different answers for a given machine. The host check runs against `backends`, and an unsupported backend **blocks** install rather than warning.
- 2026-09-15 · supervision · **one heavy group at a time** — unified memory is shared and finite; the arithmetic is stated before it is enforced.
- 2026-09-15 · supervision · **a `main` process is never auto-restarted, and never restarted on a failed health check alone** — an eight-minute generation must survive a slow probe.
- 2026-09-15 · supervision · **re-adopt survivors after a daemon restart, verifying pid + process start time + pgid** — `kill -9` on the daemon leaves children alive; checking pid alone eventually signals an unrelated process that inherited the number.
- 2026-09-15 · supervision · **health probes support path, tcp and exec** — a worker has no HTTP endpoint.
- 2026-09-15 · supervision · **`busy` probe is optional but recommended** — liveness is not occupancy. h3 studio may be running and holding nothing, or running and holding 21 GB; without this the switch dialog guesses. [evidence: h3 dry run]
- 2026-09-15 · storage · **one SQLite file for all metadata, directories for all bytes; never BLOBs** — the query surface is genuinely relational (gallery feeds, provenance graphs, reclaim set-differences, FTS); a 2 GB video in a row breaks Range streaming, backup and hardlink adoption. [supersedes: an earlier JSON-document recommendation]
- 2026-09-15 · storage · **driver `modernc.org/sqlite` behind `database/sql`** — pure Go keeps `CGO_ENABLED=0`, cross-compilation, CI and the Electron build trivial; swapping to the cgo driver later is one line.
- 2026-09-15 · storage · **WAL, `synchronous(NORMAL)`, `busy_timeout(5000)`, `foreign_keys(ON)`; one write connection, separate read pool** — `foreign_keys` is off by default in SQLite, and without it every `ON DELETE RESTRICT` is inert.
- 2026-09-15 · storage · **dedup is `UNIQUE(sha256)`; there is no stored reference count** — a counter drifts the first time a transaction is interrupted; the truth is derivable exactly.
- 2026-09-15 · storage · **media: content-addressed blob plus a human-readable hardlink under `library/`** — same inode, no copy; the CAS path gives integrity, the library path gives a person somewhere to look.
- 2026-09-15 · storage · **all studio state goes through the SDK; `sessions` is a platform table** — being the only studio whose author got atomic writes right is not a property that scales to ten. Standalone uses the same schema at `./.helm/helm.db`, which makes later adoption an import rather than a translation.
- 2026-09-15 · storage · **four OS-resolved roots (data, cache, logs) plus models; `library` defaults to `~/helmstudio`** — cache dirs are excluded from backup and may be purged, which is right for derived files and wrong for blobs. The library is the one root chosen for discoverability over convention.
- 2026-09-15 · weights · **managed or linked, same row, different `source`** — a 60 GB checkpoint you already have should not be downloaded twice.
- 2026-09-15 · weights · **no delete path ever follows a symlink; linked directories are read-only** — deleting a user's own checkpoint is unrecoverable.
- 2026-09-15 · weights · **absolute paths substituted into commands; nothing symlinked into a studio checkout** — a symlink inside the checkout collides with `git pull` on update.
- 2026-09-15 · packages · **three packages, one-way dependency: `helm-css` → `helm-runtime-sdk` → `helm-ui-sdk`** — none of the four studios has a front-end toolchain, and release cadences genuinely differ.
- 2026-09-15 · packages · **only the runtime SDK knows the wire format; components receive a client, never construct one** — an API change then regenerates one package and leaves components untouched.
- 2026-09-15 · timeline · **framework owns the document and the export pipeline; `helm-ui-sdk` ships the editor** — a sequence made from four studios is nobody's studio document and must survive uninstalling half of it.
- 2026-09-15 · timeline · **conform to a declared target, with a stream-copy fast path when legal** — a run of takes from one studio is the common case and should cost seconds.
- 2026-09-15 · delivery · **browser at 127.0.0.1:8700 is the reference implementation; Electron is a window plus native chrome** — no feature may be reachable only from the app.
- 2026-09-15 · delivery · **single machine only** — loopback alone is not sufficient: `Host` and `Origin` checks plus a `SameSite=Strict` cookie close the browser CSRF hole.
- 2026-09-15 · scope · **macOS Apple Silicon at launch; Linux is a short hop, Windows is a real port** — Windows has no process groups or signals and `build[].run` assumes a POSIX shell.

Three of four manifests point it at an endpoint that answers 200 unconditionally (`/api/queue`, `/api/health`) — if 200 means busy, all three read as permanently busy. Applied for all three anyway, for consistency and because the one-heavy-group-at-a-time rule needs to bind to *something* — but this reinterprets what the field means rather than following its stated definition, and deserves sign-off rather than standing as an unreviewed judgement call.

Undecided whether the daemon activates the created venv before running `build[]`, or a manifest must reference `{venv}` explicitly (which would need adding to `build[].run`'s own schema description first).

- **Raised in M2: processes with `autostart: false` are never started.** There is no API path to start one on demand; a process that depends on one refuses the launch.
- **Raised in M2: a log compaction racing the studio's own appends can lose or misplace a line written in a microsecond window next to the elision marker.** Removing the race needs the studio to write to something other than a file the daemon rewrites (a pipe does not survive the daemon), or punching holes (`F_PUNCHHOLE`/`fallocate`), which is filesystem-specific.
- **Raised in M2: a studio that sets `Setpgid` on its own children takes them out of the group helmstudio signals.** 08 lists h3c-studio doing exactly that for render, interactive and shell children as a pass for R26, and M2's brief calls it "the floor". But `Setpgid` in h3studio makes each render its own process group, so a SIGTERM or SIGKILL to h3studio's group does not reach a running `h3` render: it dies only if h3studio's own SIGTERM handler kills it. After the SIGKILL escalation (a studio that overruns its 10 s grace), or a crash of h3studio, the render and its 21 GB survive as an orphan nothing tracks. Not verifiable without h3 on the machine. Options: ask studios not to `Setpgid` their children (they inherit the studio's group), track descendants by session instead of group (`setsid` at spawn, then signal by session), or accept it and document the studio's SIGTERM handler as the only guarantee.
- **Raised in M2 review: a manifest cannot declare that a studio needs a secret such as `HF_TOKEN`.** 05 §10 allows "no ambient Hugging Face token unless the manifest declares it needs one"; the schema has no field for it, so under the environment allowlist no studio receives one. A schema change (and a Keychain-backed injection rather than inheriting the daemon's variable) is needed before a studio that downloads at run time can work.
- **Raised in M2 review: grace is one daemon-wide 30 s.** A studio that needs longer to stop has no way to say so; a per-process `stop_grace_s` would be a schema change. Decide together with the nested-`Setpgid` entry above.
- **Raised in M2 review: should helmstudio ever signal the surviving members of a group whose recorded leader is gone?** They are reported now. The kernel cannot reuse a group id while any member lives, so signalling them would be safe by identity, but 02 §7 says "nothing is signalled", and they may be the only copy of a render still finishing.
- **Raised in M2 review: a run log is compacted only while a daemon tails it.** While the daemon is down a studio's log grows without bound (1 MB/s overnight is 30 GB); the next daemon compacts it on its first read after re-adoption.
- **Raised in M2 review: the API has no authentication until M9.** Requests without an `Origin` header are allowed so `curl` works, so any local process — including another account on the same Mac — can launch and stop studios. Host and Origin checks stop web pages, not local processes.

- **Raised in M3: a build step outlives a daemon killed with `kill -9`.** The step leads its own process group, as every spawn must, and nothing ties it to the daemon. `step_runs` has no pid, pgid or start time, so the next daemon's sweep records the step `interrupted` but cannot find or stop the process, and a Retry while it still runs starts a second build in the same checkout. Reproduced with the real binary. Options: add `pid`, `pid_start_time` and `pgid` to `step_runs` and have the sweep stop a verified survivor, as re-adoption does for processes; or refuse Retry while a recorded step could still be alive.

Decisions made while building M8a, each a judgement call for the reviewer to confirm or overturn:

- 2026-09-16 · code · **the pipeline is three packages: `internal/timeline` decides, `internal/export` carries out, and `internal/api/studioapi` enforces.** The rules, the snapping, the legality predicate and the ffmpeg argument list are pure functions over the document and the probed facts; `internal/export` finds ffmpeg, probes a file and runs one render in its own process group; the operations stay where every other one is enforced — the reason being that everything except the running is then checkable in the gate without a model, a GPU or a person watching.
- 2026-09-16 · export · **the copy path is one ffmpeg invocation: the concat demuxer for the picture with `-c:v copy`, and the same clips opened again for their sound, which goes through the graph** — one process, one output, no intermediate file, and the sound is conformed exactly as it is on the slow path.
- 2026-09-16 · export · **the graph's own choices, none of which 05 §6 states.** Each was found by running it:
  - **`settb=AVTB` ends every chain.** `xfade` refuses two inputs whose timebases differ, and one side that has been through a `concat` counts in different units from a fresh clip.
  - **`setparams` tags the frames**, rather than the encoder being asked for the colour afterwards: videotoolbox writes its own VUI and drops primaries and transfer, so an export came out tagged bt709 for the matrix and nothing else.
  - **A clip's sound is placed by prefixing exactly as much silence as its position and concatenating**, not with `adelay`, which names whole milliseconds: a frame at 24 fps is 41.666 ms, so every clip would land a third of a millisecond out and the error would accumulate.
  - **Each clip's sound is padded and then cut to its picture's length** (`apad` then `atrim`), because a take's sound rarely ends with its picture — h3's outlast theirs by 8 ms.
  - **A dissolve's sound is a fade out on one side and a fade in on the other**, summed by the mix, which is what a crossfade is; `acrossfade` cannot be used where every clip is already a separate input of one `amix`.
- 2026-09-16 · api · **the router tries a route whose parameter carries an action before the bare one** (`internal/api/studioapi/handler.go`): `/timeline/{id}` and `/timeline/{id}:plan` both match the same path, and without the preference a `GET` plan was read as an id ending in `:plan` and refused for not looking like one. Every earlier action was a `POST` on a path whose bare route had none, which is why this never showed. Found by the conformance suite's route sweep (M4 second review #4).
- 2026-09-16 · security · **the same-origin proxies forward `timeline` and `timeline:append`** in all three runtime SDKs. M6 Q10's allowlist is by first path segment, so a new operation is invisible to a studio's page until it is added; the conformance suite's proxy case catches exactly that, and did.
- 2026-09-16 · media · **a video's thumbnail is a poster frame taken a tenth of the way in**, read as `rawvideo` and scaled by M4's own thumbnailer, so an image's thumbnail and a video's are the same kind of file. Bytes ffmpeg cannot read a frame from answer 501 `unsupported`, as an image the standard library cannot decode already does, rather than reporting a fault of the daemon's. A tenth in, because a clip that fades up from black gives a black poster at zero.
- 2026-09-16 · export · **the minimum ffmpeg is major 6**, which is where every filter and option this pipeline names has been available. The goldens are pinned separately, to the major and architecture that made them.
- 2026-09-16 · storage · **schema v6 ships as `internal/store/migrations/0006_timeline.sql`**, with the DDL written into 02 §5 first: `timelines` gains `studio_id` and `deleted_at`, `timeline_revisions` arrives, `jobs` gains `pid`, `pid_start_time`, `pgid` and `work_path`, and `log_files.kind` gains `export`, which needs that table rebuilt as v4 rebuilt it.
- 2026-09-16 · tests · **tests written before M8 and edited, named here for sign-off.** Each keeps its own check under the contract as M8 changed it:
  - M1's `TestMigrationsFromEmptyCreateSchemaV1` pins version 6 and lists `timeline_revisions`, `idx_timelines_studio` and `idx_jobs_subject` — the same kind of edit M2, M3, M4 and M6 were directed to make when their migrations landed.
  - M4's conformance case `TestThumbnailsForImagesAndUnsupportedForVideo` is renamed `…AndBytesThatAreNotAVideo` and now holds what Q6 makes true: an image is scaled, a video gets a poster, and bytes that are not a video are refused as unsupported.
  - M4's cross-studio route sweep gains a sequence, an export job written straight into the store, bodies for the timeline's writes and an `If-Match` header for the two operations that require one — otherwise its new routes would refuse for a missing precondition rather than for ownership.

### M8b · decided at its kickoff, and judgement calls while building (2026-09-16)

- 2026-09-16 · ui · **the preview plays each clip's own bytes in the browser against one clock: no ffmpeg, no render, no new operation.** A small window of media elements — what is under the playhead, and the next clip on each track parked on its in point — is kept agreeing with a pure function, `frameAt(doc, t)`, which says which pictures show at what opacity and which sounds play at what gain. A dissolve is a crossfade of the two sides, reading each clip's handle past its edit point; a still is an image for its hold; the letterbox is the target's aspect ratio on the component's inset ground. Rejected: Media Source Extensions over remuxed fragments, and a rendered proxy — both need ffmpeg on the daemon and a new operation, a render waits on every edit, and Q5 keeps creating and editing a sequence working without ffmpeg, which a preview that needed it would quietly break. It works because every clip M8's demos use is something a browser plays as it is (the kickoff's "What I measured"). **Costs, stated in the component:** it is a preview, not a render — a cut lands within a frame, colour is not converted, a codec the browser cannot decode is a gap with a note, and gain above 0 dB previews at 0 dB (see the open entry on `connect`). [decides: 04 §5's "gapless preview across cuts", left to this kickoff]
- 2026-09-16 · ui · **`helm-timeline`'s structural interface** is `timeline.get` and, with `editable`, `timeline.update`; optionally `timeline.revert` (Undo, Redo), `timeline.plan` (the chip), `timeline.export`, `timeline.exports` and `timeline.cancelExport` (Export), `timeline.append` (`el.append()`), `assets.read` (the preview) and `me.get` (the caller's own hue). - 2026-09-16 · ui · **a write sends the whole of `tracks` as a merge patch with the `If-Match` it read; V1's clips go without `at`**, because the daemon lays a contiguous track and refuses a gap, so a position sent with a trim would turn it into a refusal. What comes back replaces what was drawn. **A conflict** reads the sequence again and says so, and does not replay the edit onto a document nobody on the page has seen. **A refusal** restores the daemon's last document and shows its own sentence. Edits queue, each applied to the latest answer, so three quick nudges are three frames.
- 2026-09-16 · ui · **Undo reverts to the revision before the one showing, and Redo walks forward through what this editor undid; any new edit ends Redo** (M8 Q10). - 2026-09-16 · ui · **the editor does not embed a picker.** Add emits `add-request`, and the page calls `el.append(assetId)`, which is `:append` with `timeline_id` (M8 Q19). What goes into a sequence is the studio's to decide (04 §11 rule 5), and helm-gallery's picker already exists for a page to use.
- 2026-09-16 · ui · **snapping mirrors the daemon's arithmetic exactly**: the exact ratios for 23.976, 29.97 and 59.94, and Go's rounding of a negative half away from zero, which JavaScript's `Math.round` does not do. - 2026-09-16 · ui · **keys:** `[` and `]` shorten a clip from its start and end by a frame, and with Shift lengthen it; Alt+←/→ moves a clip (a place on V1, a frame on a sound track, a second with Shift); Delete removes it; Enter selects it; Space plays; ←/→ step a frame, a second with Shift; Home and End; Cmd/Ctrl+Z undoes, and Shift+Cmd/Ctrl+Z or Ctrl+Y redoes. - 2026-09-16 · ui · **the lanes are a scroll container only when zoomed past the page.** At fit zoom there is nothing to scroll, and an `overflow: auto` element is a layer of its own under the panel's rounded clip; the last one-in-eighteen golden difference was at those corners.

## 2026-09-18 · The Mac app is a native shell, not Electron

Decided before M9 is expanded, which is the last moment it is free: the shell is not built, so this supersedes a delivery decision rather than a body of code. 01 §12 R73 and 03 §14's table of what the shell adds are amended; 02 §11's "anything the Electron shell knows", and the asides in 02 §9, 06 §3 and 06 §11 that name the Electron build, say "the shell" and "the app bundle" instead. `docs/agents/milestones/09-mac-app-and-release.md` is amended at its Shape, its Known at freeze and its Review focus. The briefs of milestones already built are a record of what they were told and are left as they are.

- 2026-09-18 · delivery · **the human's decision: `helmstudio.app` is a native Swift bundle around a `WKWebView`, not Electron. The browser at `127.0.0.1:8700` stays the reference implementation, no feature is reachable only from the app, and the shell holds no business logic** — [supersedes: 2026-09-15 · delivery · browser at 127.0.0.1:8700 is the reference implementation; Electron is a window plus native chrome]. Electron's one real advantage is a shell that also runs on Windows and Linux, and helmstudio cannot spend it: what blocks Windows is the daemon, not the window — "Windows has no process groups or signals and `build[].run` assumes a POSIX shell" — so the portable shell would wrap a daemon that does not run there, and every other platform takes the web version, which is the reference implementation anyway. What is left is cost. R71 asks for a hardened runtime, and an Electron bundle is a framework of nested Mach-O binaries and helper apps signed with `allow-jit`, `allow-unsigned-executable-memory` and usually `disable-library-validation` — entitlements that exist to weaken the runtime R71 turns on; a native bundle signs one app and the binaries it embeds. `web/` is vanilla JS served from Go's `embed` with no build step anywhere in that path, and Electron would add npm, a lockfile and a Chromium whose CVEs are ours to track to the one part of the repo that has none of it. WKWebView is the WebKit the browser path is already tested against, so the app adds no third engine. R73 is why this costs a decision rather than a rewrite: a shell with no business logic in it has none to port.
- 2026-09-18 · delivery · **the app authenticates the way the browser does — the shell reads the nonce from the handshake, loads a one-time URL, and the daemon answers `Set-Cookie`, `HttpOnly`, `SameSite=Strict`. The renderer still never sees a token, and M9 ships one auth flow rather than two** — WebKit has no `onBeforeSendHeaders`: a `WKWebView` cannot rewrite the headers of an ordinary http request, so the injection M9 recorded at freeze has no native equivalent and had to be replaced rather than translated. Of the three ways to replace it, a `WKURLSchemeHandler` makes the page's origin `helm://`, which `internal/api/api.go`'s Origin check would then refuse and which would leave the studio frame mixed-scheme; a `WKScriptMessageHandler` bridge puts request handling in the shell, against R73. The cookie is the exchange the browser path needs regardless. It also narrows the M9 review question "can the renderer obtain the token by any route": a `WKWebView` with no script-message handler and no scheme handler registered has no bridge to leak one through, where Electron's preload is the known surface.
- 2026-09-18 · delivery · **what the shell needs from the daemon it reads over `URLSession` and SSE, hand-written against `api/openapi.yaml`; no Swift SDK is generated and the generator does not gain a fourth target** — this is the price of the choice, named rather than hidden. The menu bar item and the Dock's progress (01 R70) are the only shell surfaces that need daemon state, which is a few endpoints and the event stream; in Electron the main process would have used the published Node SDK instead. A fourth generated client would be a package to publish, version and keep in step for one consumer that never leaves this repo.
- 2026-09-18 · delivery · **Sparkle, with an EdDSA-signed appcast, replaces `electron-updater` for R72** — what R72 actually constrains is that the update ships shell, daemon and bundled registry together, and that is unchanged.

**Raised, not decided:**

- **A cookie is not port-scoped, and every studio serves on a port of the same host.** RFC 6265 leaves the port out of a cookie's scope, so a session cookie set on `127.0.0.1:8700` is sent with every request to `127.0.0.1:<any port>` — which is every studio's own server, running code the approval screen warned about but did not sandbox. A studio could read the launcher's cookie out of its own inbound requests and then use it from its own process, where the Origin check does not apply, because a request with no `Origin` is allowed so `curl` works (raised in M2 review, above). That would leave M9's auth closing the browser hole it was written for and not the local-process hole recorded alongside it. This is not a consequence of the shell decision — it lands on the browser path identically — but M9 is where the cookie is introduced, so it has to be answered there. Directions, none chosen: serve studios on a different loopback host, since cookies *are* host-scoped and all of `127.0.0.0/8` is loopback on macOS; or keep the cookie for the browser and give the app a bearer token by some route that does not put request handling in the shell; or require a header on state-changing routes that no local process can obtain without already holding the cookie, which on inspection may not exist.
- **Where the app lives in the tree, and its minimum macOS version.** `.gitignore` still names `/packages/app/release/`, which is an electron-builder output path. The deployment target decides whether the view is SwiftUI's `WebView` (macOS 26+) or `WKWebView` behind `NSViewRepresentable`, which is the lower-risk path and the one everything above assumes. Both are M9 kickoff questions.

- 2026-09-19 · weights · **a linked directory is read through its symlinked subdirectories: one whose target stays inside the directory is descended, and one that leaves it refuses the link where files are linked out one at a time (`local_path`) and is skipped where the directory is linked whole (`:link`)** — MiniMax-H3 ships deduplicated, with `FL2VA/{tokenizer,processor,text_encoder,audio_vae,video_vae}` symlinked to `../Ref2VA/…`. `filepath.WalkDir` neither descends such an entry nor matches it, so the install linked FL2VA without its tokenizer, reported the directory present, and the first render failed on `FL2VA/tokenizer/tokenizer.json`. A *file* symlink still counts by its target wherever it points, which is what a Hugging Face snapshot needs. [extends: 2026-09-15 · weights · "a directory links when every `files` pattern matches at least one regular file (a file symlink, as in a Hugging Face cache snapshot, counts by its target)"]
