# Decision log

Append-only. One line per decision: the date, the decision, and the reason. Never delete an entry — supersede it with a new one that says what it replaces.

Read it before starting on anything and add to it when you finish. Whatever is not written down here gets re-decided later, differently, by whoever picks the work up next — including you, six months from now.

## 2026-09-15 · design sprint frozen

- 2026-09-15 · daemon · **Go, stdlib-first, single binary on 127.0.0.1:8700** — matches h3c-studio and iris-studio; zero-install for users; subprocess supervision and reverse proxy are stdlib-shaped.
- 2026-09-15 · manifest · **`processes[]` replaces a single `run` block** — a studio is not always one server; an engine sidecar or a queue worker must be a data change, not a Go special case. `run:` survives as sugar for a single main process.
- 2026-09-15 · manifest · **manifest lives in the studio's own repo as `helmstudio.yaml`; the registry holds pointers** — two copies drift, one does not; a studio can announce a new build step without a helmstudio release.
- 2026-09-15 · manifest · **three resolution sources, first match wins: local file → in-repo → registry inline** — most repos will never ship a manifest, so anyone must be able to write one. A manifest is a description of a repo, not a file only its author can provide.
- 2026-09-15 · manifest · **`build[].shell` declared now, default `sh`** — a later Windows port must not invalidate every manifest ever written.
- 2026-09-15 · runtime · **`framework` and `backends` are separate fields** — PyTorch-on-cuda and PyTorch-on-mps are entirely different answers for a given machine. The host check runs against `backends`, and an unsupported backend **blocks** install rather than warning.
- 2026-09-15 · supervision · **one heavy group at a time** — unified memory is shared and finite; the arithmetic is stated before it is enforced.
- 2026-09-15 · supervision · **a `main` process is never auto-restarted, and never restarted on a failed health check alone** — an eight-minute generation must survive a slow probe.
- 2026-09-15 · supervision · **re-adopt survivors after a daemon restart, verifying pid + process start time + pgid** — `kill -9` on the daemon leaves children alive; checking pid alone eventually signals an unrelated process that inherited the number.
- 2026-09-15 · supervision · **health probes support path, tcp and exec** — a worker has no HTTP endpoint.
- 2026-09-15 · supervision · **`busy` probe is optional but recommended** — liveness is not occupancy. h3 studio may be running and holding nothing, or running and holding 21 GB; without this the switch dialog guesses. [evidence: h3 dry run]
- 2026-09-15 · storage · **one SQLite file for all metadata, directories for all bytes; never BLOBs** — the query surface is genuinely relational (gallery feeds, provenance graphs, reclaim set-differences, FTS); a 2 GB video in a row breaks Range streaming, backup and hardlink adoption. [supersedes: an earlier JSON-document recommendation]
- 2026-09-15 · storage · **driver `modernc.org/sqlite` behind `database/sql`** — pure Go keeps `CGO_ENABLED=0`, cross-compilation, CI and the Electron build trivial; swapping to the cgo driver later is one line.
- 2026-09-15 · storage · **WAL, `synchronous(NORMAL)`, `busy_timeout(5000)`, `foreign_keys(ON)`; one write connection, separate read pool** — `foreign_keys` is off by default in SQLite, and without it every `ON DELETE RESTRICT` is inert.
- 2026-09-15 · storage · **dedup is `UNIQUE(sha256)`; there is no stored reference count** — a counter drifts the first time a transaction is interrupted; the truth is derivable exactly.
- 2026-09-15 · storage · **media: content-addressed blob plus a human-readable hardlink under `library/`** — same inode, no copy; the CAS path gives integrity, the library path gives a person somewhere to look.
- 2026-09-15 · storage · **all studio state goes through the SDK; `sessions` is a platform table** — being the only studio whose author got atomic writes right is not a property that scales to ten. Standalone uses the same schema at `./.helm/helm.db`, which makes later adoption an import rather than a translation.
- 2026-09-15 · storage · **four OS-resolved roots (data, cache, logs) plus models; `library` defaults to `~/helmstudio`** — cache dirs are excluded from backup and may be purged, which is right for derived files and wrong for blobs. The library is the one root chosen for discoverability over convention.
- 2026-09-15 · weights · **managed or linked, same row, different `source`** — a 60 GB checkpoint you already have should not be downloaded twice.
- 2026-09-15 · weights · **no delete path ever follows a symlink; linked directories are read-only** — deleting a user's own checkpoint is unrecoverable.
- 2026-09-15 · weights · **absolute paths substituted into commands; nothing symlinked into a studio checkout** — a symlink inside the checkout collides with `git pull` on update.
- 2026-09-15 · packages · **three packages, one-way dependency: `helm-css` → `helm-runtime-sdk` → `helm-ui-sdk`** — none of the four studios has a front-end toolchain, and release cadences genuinely differ.
- 2026-09-15 · packages · **only the runtime SDK knows the wire format; components receive a client, never construct one** — an API change then regenerates one package and leaves components untouched.
- 2026-09-15 · timeline · **framework owns the document and the export pipeline; `helm-ui-sdk` ships the editor** — a sequence made from four studios is nobody's studio document and must survive uninstalling half of it.
- 2026-09-15 · timeline · **conform to a declared target, with a stream-copy fast path when legal** — a run of takes from one studio is the common case and should cost seconds.
- 2026-09-15 · delivery · **browser at 127.0.0.1:8700 is the reference implementation; Electron is a window plus native chrome** — no feature may be reachable only from the app.
- 2026-09-15 · delivery · **single machine only** — loopback alone is not sufficient: `Host` and `Origin` checks plus a `SameSite=Strict` cookie close the browser CSRF hole.
- 2026-09-15 · scope · **macOS Apple Silicon at launch; Linux is a short hop, Windows is a real port** — Windows has no process groups or signals and `build[].run` assumes a POSIX shell.

## Open, not yet decided

- ffmpeg licensing: LGPL + videotoolbox (leaning) vs GPL + x264. **Gates M8 and what can be bundled in a signed .dmg.**
- Dedup headline: check whether the four manifests share a Hugging Face repo before promising a number.
- Reverse proxy: add `--base-path` to the four studios, or keep own-origin tabs.
- Vendoring `uv`: bundle a pinned binary vs detect and instruct.
- Weight verification: size + etag (leaning) vs SHA256 behind an explicit Verify action.
- **`studios/*.yaml`: bare pointer (`id`/`repo`/`ref`/`certified`, per `docs/design/05-sdk-and-custom-studios.md` §5a's own example) vs the full manifest M0 actually wrote there.** `schema/manifest.json` has no `certified` field and would reject one (`additionalProperties: false` — confirmed by hand); `helm validate studios/*.yaml`'s literal DoD only works against a full manifest. Raised in `docs/agents/reports/00-contracts.md`, not resolved: M0 kept full manifests (closest schema-valid approximation of §5a's "inline manifest carried by the registry pointer" source, since none of the four repos has published its own `helmstudio.yaml`) and added `ref`, which the schema does support.
- **One `weights[]` entry can now need to share `(hf_repo, revision)` with another that wants a different file subset of the same repo** (h3's FL2VA/Ref2VA, ltx's base files vs the optional dev transformer) — `docs/design/02-data-model.md` §10's dedup rule keys `model_artifacts` on `(hf_repo, revision)` alone and treats a second binding at the same key as "nothing to download." Whether a second binding with a different `files` allow-list should trigger a fetch of just the missing files, or needs its own artifact row, is undecided.
- **`busy`'s response has no contract** (`schema/manifest.json`'s own description is silent on shape). Three of four manifests point it at an endpoint that answers 200 unconditionally (`/api/queue`, `/api/health`) — if 200 means busy, all three read as permanently busy. Needs a documented response shape (a boolean at a known key? a specific status code?) before the switch dialog can use any of them.
- **Does `{ports.x}` in a process `cmd` require that process to also `depends_on` x?** `docs/design/02-data-model.md` §7 assigns a port only at `queued` → `starting`, so a process substituting a sibling's port without depending on it can be substituted a port that doesn't exist yet. `helm validate` currently allows this.
- **`docs/agents/milestones/00-contracts.md` rule 3 ("exactly one process has role: main") vs `docs/design/05-sdk-and-custom-studios.md` §9 criterion 4 ("at least one main process").** `helm validate` implements the milestone's literal text; criterion 4 disagrees. Whichever is right should replace the other, not coexist.
- **Marking a thin wrapper process `heavy: true` when the memory-holding work happens in a child process it spawns** (h3, iris, ltx all fit this; only AuK's server holds weights in its own process). Schema's own description ties `heavy` to "the process that holds the model," which none of h3/iris/ltx's declared process literally does. Applied for all three anyway, for consistency and because the one-heavy-group-at-a-time rule needs to bind to *something* — but this reinterprets what the field means rather than following its stated definition, and deserves sign-off rather than standing as an unreviewed judgement call.
- **How a `build[]` step sees the per-studio `python.version` environment.** ltx's `uv sync --all-extras` and AuK's `uv pip install -e .` both assume an already-active venv on `PATH`; `{venv}` exists as a `process.cmd` substitution but `build[].run` documents no substitution variables at all. Undecided whether the daemon activates the created venv before running `build[]`, or a manifest must reference `{venv}` explicitly (which would need adding to `build[].run`'s own schema description first).
- **Correction to the `studios/*.yaml` pointer-vs-full-manifest entry above: M0's full manifests are a placeholder, not a reading of the design.** That entry called them the "closest schema-valid approximation" of §5a's inline-manifest source; no design text supports that. They are full manifests only because `schema/manifest.json` has no pointer shape to validate against and M0's gate runs `helm validate studios/*.yaml`. The schema's own top-level description argues the other way ("The registry holds pointers to these, never copies"). Each of the four files now opens with a PLACEHOLDER SHAPE header naming this entry. Still open. [supersedes: the wording of the pointer-vs-full-manifest entry above, not the question]
- **Proposal for M4's first review, not settled: tag every `api/openapi.yaml` operation `studio-api` or `launcher`, so SDK generation (R51) can exclude launcher operations from `helm-runtime-sdk`.** Supported by: `docs/design/04-packages.md` §1's table, which scopes `helm-runtime-sdk` to "state, records, assets, gallery, jobs, timeline, events," with no install, launch or settings; `docs/design/01-prd.md` R51 and `docs/design/05-sdk-and-custom-studios.md` §5, which generate all three clients from one document, so without some marker every operation in it lands in every client. Not settled by any design text: (a) whether launcher operations belong in this document at all, rather than a second one; (b) where `/me`, `/sessions`, `/handoff` and `/inbox` sit, since 04 §1's list names none of them and M0 tagged them `studio-api` on its own reading; (c) 05 §7 puts framework-only surfaces like `/timeline/{id}:open` in the SDK, degrading to 501 when embedded, so "launcher" cannot mean "needs the daemon." M4 may keep, change or drop the split.

## 2026-09-15 · M0 contracts

- 2026-09-15 · tooling · **`github.com/santhosh-tekuri/jsonschema/v5` validates manifests against `schema/manifest.json`** — the schema is draft 2020-12 with `oneOf`/`anyOf`/`allOf`/`$ref` throughout; a hand-rolled validator risks silently diverging from the one document every later milestone is checked against, which is the failure M0 exists to prevent.
- 2026-09-15 · tooling · **`gopkg.in/yaml.v3` parses manifests** — decodes YAML mappings as `map[string]interface{}`, not `map[interface{}]interface{}`, which is what lets a parsed manifest round-trip through `encoding/json` for schema validation without a translation layer.
- 2026-09-15 · manifest · **studio ids `iris-studio`, `ltx-studio`, `auk-studio`** — the PRD's own example fixes `h3-studio`; the other three needed a slug chosen. `id` is immutable once published, so this is recorded rather than left implicit in a YAML file.
- 2026-09-15 · manifest · **h3 studio's declared weight is 196 GB, not the 60 GB in docs/design/01-prd.md §13 and docs/design/08-h3-dry-run.md** — measured directly (`du -sh`) against the checked-out `MiniMaxAI/MiniMax-H3` on disk (FL2VA 62 GB + Ref2VA 134 GB). The design examples were not re-verified against bytes on disk; `studios/h3-studio.yaml` now is.
- 2026-09-15 · tooling · **`helm validate` locates `schema/manifest.json` via a path relative to its own source file, not `go:embed`** — an embed pattern cannot contain `..`, and `schema/` is a sibling of `internal/`, not a descendant, so embedding it needs a loader file placed inside `schema/` itself, which is outside this milestone's file list. `HELM_SCHEMA_PATH` overrides it. Correct for `go test`, `make gate`, and a `bin/helm` built fresh from a checkout — the only ways helm runs today; revisit when `helm` ships as a distributed binary (M9). **Confirmed by peer review to break under `-trimpath`** (fails loudly, names `HELM_SCHEMA_PATH`) **and to silently use the wrong worktree's schema if a binary built in one checkout runs against manifests in another** — real, not yet fixed; still out of scope while embedding needs a file inside `schema/`.
- 2026-09-15 · manifest · **h3's weight is two entries, not one — `fl2va` (62 GB, required) and `ref2va` (134 GB, `optional: true`), both `dest: MiniMax-H3`** — supersedes the 2026-09-15 entry above declaring a single 196 GB weight. `server/model.go`'s own comment says "FL2VA always, Ref2VA for references"; a peer review caught that the single-weight declaration didn't reflect that. Two entries sharing one `dest` is how the schema expresses "same directory, different file subset" given weights[] has no other way to say it; see "Open, not yet decided" for the dedup-key question this raises for M3.
- 2026-09-15 · manifest · **`ref` pinned on all four manifests to the exact commit each repo was read at** (h3 `a6eb54f3c9d8c3e711bab22574ec6599399a03f9`, iris `b4f857f4d484f91cbbd6e48ba79f3879e49a253c`, ltx `bc82d75f0182e3631a6cbcd3b704e74445a32c5f`, AuK `61ae02a65c947a8c499a27f963165b351416a146`) — `docs/design/05-sdk-and-custom-studios.md` §5a: "a registry entry always pins one." A peer review caught that M0's first pass left it out of all four.
- 2026-09-15 · manifest · **h3's build step is `make -j8` in `h3c`, not `make mps`** — `h3c/Makefile` has no `mps` target (`all`, `test`, `parity`, `real-parity`, `clean` are the only ones; `all` is default). The wrong command was copied from `docs/design/01-prd.md` §13's illustrative example instead of read from the repo's own Makefile — a peer review caught this; it is the one place this milestone's report claim ("written from the real repositories, not the design docs' examples") was false. `ffmpeg` added to `requires.tools` for the same reason (`server/media.go` refuses to run without it; README confirms it as a hard requirement, not mentioned in the design docs' examples at all).
- 2026-09-15 · manifest · **AuK's `runtime.backends` is `[mps, cpu]`, not `[cuda, mps, cpu]`** — the code's own device-fallback chain does support cuda, but this manifest's `requires.os` is `[darwin]` only, and no darwin/arm64 host can ever provide a cuda backend. Declaring it was correct-from-the-code but dead under this manifest's own OS gate; a peer review caught the inconsistency.
- 2026-09-15 · manifest · **`handoff.send` removed from iris and AuK's `capabilities`** — added on a first pass by analogy with h3's set, but `docs/design/08-h3-dry-run.md` never declares it even for h3, and `docs/design/07-platform-services.md` §5 describes cross-studio handoff as a launcher-initiated action ("Use in…" on a gallery item) that works even for a studio that never calls `POST /handoff` itself — so there is no real evidence either studio's own code needs it. Criterion 9 (`docs/design/05-sdk-and-custom-studios.md` §9) is Required: "the minimum capabilities it uses, and no more." A peer review caught the gap between "intent" and "no more."
- 2026-09-15 · manifest · **AuK's backends: `[mps, cpu]` on darwin/arm64, not `[cuda, mps, cpu]` on a widened `requires`** — a choice between two defensible readings, not a correction. `web/server.py:53` (`_default_device`) tries cuda first, and AuK's README reports peak VRAM on an NVIDIA A800, so "backends it genuinely supports" includes cuda. Widening `requires` to linux/amd64 would keep it. Chose the darwin/arm64 manifest because `docs/design/01-prd.md` §13's table lists AuK as `mps`, `cpu`, and §14 makes "No Windows or Linux GPU support at launch" a v1 non-goal; the design is the contract, and a linux/amd64 `requires` would declare a host nobody has checked this studio on. Cost: the manifest understates what the code does, and a later Linux+CUDA leg has to change this file. A human may reasonably overrule. [supersedes: the reason given in the AuK backends entry above — "dead under this manifest's own OS gate" assumed the OS gate, which was itself the choice]
- 2026-09-15 · tooling · **`helm validate` asserts `format` (`Compiler.AssertFormat = true`), so `format: uri` on `repo` and `license_url` rejects non-URIs** — closest thing in M0 to a contract change. It does not edit `schema/manifest.json`, but draft 2020-12 treats `format` as an annotation by default, so a manifest a default-configured validator accepts (`repo: "not a uri at all"`) is rejected here. Reason: the schema author wrote `format: uri` on a field whose value is handed to `git clone`, and an annotation nobody checks lets the failure surface at install time instead of at validate time. Outlives this change because every other validator of the same schema (the daemon's loader in M1, registry CI, `helm dev`) must make the same choice or they disagree on which manifests are valid. Needs sign-off; reverting is one line plus the `schema_invalid_uri.yaml` fixture.
- 2026-09-15 · tooling · **`helm validate` rejects duplicate `processes[].name` and duplicate `weights[].name` (rule `unique-names`), beyond the milestone's seven** — `process.name`'s schema description says "Unique within the studio. Exposed to siblings as {ports.<name>}," which `uniqueItems` cannot express. For weights the schema says only "The placeholder key: {models.<name>}"; uniqueness there is inferred, since two weights sharing a key make `{models.<name>}` ambiguous. Outlives this change: the supervisor (M2) and weight binding (M3) can then key on name without handling duplicates. A human may reasonably narrow it to processes only.
- 2026-09-15 · tooling · **`helm validate` rejects any `{...}` in `process.cmd` outside the set `schema/manifest.json` names (rule `known-placeholder`), beyond the milestone's seven** — `process.cmd`'s description: "Template. Substitutes {port}, {ports.<name>}, {models.<name>}, {models.selected}, {root}, {data}, {venv}." Reason: an unknown key such as `{prot}` otherwise reaches the spawned process's argv as a literal string. Cost: the schema defines no escape, so a legitimate literal brace in a command, such as shell `${HOME}`, is also rejected. None of the four manifests hits this. Outlives this change because M2's template substitution has to agree with it: either it fails on the same set, or it passes unknown braces through and this rule is stricter than the runtime. Only `process.cmd` is checked; `build[].run` documents no substitutions, see the venv entry in "Open, not yet decided."

## Changes

- 2026-09-15 · M0 built the manifest schema's `helm validate` (schema validation plus the seven rules it cannot express), the four studio manifests, and the `api/openapi.yaml` outline · found one hard self-contradiction in `schema/manifest.json` itself (the `run` sugar is unusable: `processes` sits in the schema's unconditional top-level `required`, so `run:` alone always fails "missing properties: processes" regardless of the `allOf`/`not` clause that says they're alternatives) — raised in `docs/agents/reports/00-contracts.md`, not resolved in code; all four shipped manifests use `processes:` so this did not block M0.
