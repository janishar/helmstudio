Right-click menus

alpha.5 item 17 · owner 2026-11-26: "is it possible to have our own double click menu", "right click in mean", "App-wide", then "have we considered all the places for right click": every place, and "Ours everywhere" in text fields

0The rules

  1. Ours everywhere in the app: the Timeline, Gallery, Create (stage, strip, sessions, @ chips), both graphs, the Assistant chat, Models, the LoRA, voice and element libraries, and the Hub and System lists (frames 1–12); Magic on its own board (frame 13). Text fields too (frame 6): Cut, Copy, Paste, Select all, Insert @… in a prompt, spelling suggestions in the Mac app; in the browser the first Paste asks for clipboard permission. Where nothing has a menu (a heading, empty page space) right-click does nothing. Shift + right-click always shows the browser's own menu (Look up, Inspect), drawn here.
  2. One shared menu with the app's menu look (the .menu shell of the Create chip popups and Run on): a header naming what it acts on, items with an icon, the label and its shortcut key on the right, groups with separators, the danger item (Delete, Remove) last in red. A danger item does exactly what its button does today: Delete in the Gallery and Create and Remove track (with clips) open their confirm card; Remove clip and Remove marker have no card and come back with ⌘Z, as now.
  3. Only real actions. Every item calls the action the page already has (inspector buttons, the shortcut list behind ?, the Gallery's take actions, Use in…). An item tagged new on this board has no action today; the rest exist. An item that can't run now is greyed with its reason on hover rather than hidden, the same rule as greyed fields elsewhere.
  4. Submenus only where a list needs one: Use in ›, Replace with another take ›, Move to track ›, Replace with › on an @ chip. They open on hover or → and close on ←.
  5. Opens at the pointer, kept on screen (flips left or up near an edge). Esc or a click outside closes it; ↑ ↓ move, Enter picks, typing a letter jumps to the item starting with it. Focus goes back to where it was.
  6. Keyboard: the menu key or ⇧F10 opens the menu of the focused item (a clip, a card, a tile, a row, a node, the caret in a field), at its bottom-left corner (in a field, at the caret), first item focused; ↑ ↓ move, → opens a submenu and ← closes it, Enter picks, Esc closes and focus goes back. Screen readers hear it as a menu (role menu, menuitem).
  7. Right-click selects first: on something not selected it selects that one alone, then opens; on a selection it acts on the whole selection (frame 3, frame 4). The existing ⋯ buttons stay and open the same menu.
  8. Items that act at a time (New shot, Add marker, Mark in) act at the pointer's time, not the playhead; the playhead does not move.

1Timeline · a clip

  1. A shot on V1: the clip inspector's actions, in its order. Generate from this clip first: the take's offers (Extend · LTX-2.5 Extend here; whatever the clip's workflows offer, as the inspector lists them), Replace with another take › (its other takes, seed 42 / 44 / 45, the current one ticked), Redo this shot, Use in › (Last frame in…, First frame in…, then the frame's offers), Re-render…. Then the edit keys: Split at playhead S, Mark clip as range X, Leave a gap ⇧Delete, and last Remove clip Delete (ripple). All exist today.
  2. An empty slot on V1 (a lifted shot) shows New shot here (or Try this shot again after a failed run) and Remove clip; a shot still running shows only its run's state and greys the rest with "The shot is still running".
  3. An audio clip: today's ⋯ menu (Make shot, Replace with another take, Use in…, Save as voice…, Remove clip), plus the inspector's Mute and the edit keys. Move to track › lists the other audio tracks; it is the drag between tracks the lanes already do (the move op with a track), so nothing new behind it; New audio track in it is + Audio track, then the move.
  4. A linked pair (a V1 shot and its A1 sound) acts together, as selecting does today; ⌥ + right-click picks the one clip, as ⌥ + click does.

2Timeline · a gap, a track, the ruler

  1. An empty gap on a track (or past the last clip): New shot (opens New shot docked, at the pointer's time instead of the playhead), New line (New line on that track), Add clips to A2 (the side panel's Add clips for the track), Add marker M. Close gap is new: no op closes a gap today (Delete ripples only when it removes a clip); greyed "Nothing after it to move" past the last clip. On V1 there are no gaps (shots butt), so the gap menu shows on audio tracks only.
  2. A track header: the track panel's own items: Mute (Muted, ticked, when on), Add clips to A2, New line on it, Add audio track (the lanes' + Audio track), and Remove track last (with its confirm when the track has clips). V1 and A1 headers show Mute only where the inspector has it, and Remove track greyed with "V1 holds the shots" / "A1 is V1's own sound".
  3. The ruler: Add marker M, Mark in I, Mark out O at the pointer's time, Clear range ⌥X (greyed with "No range set" when there is none), the zoom keys Zoom in ⌘=, Zoom out ⌘−, Fit ⇧Z, and the two toggles Snapping N and Hover scrub ⇧S with a tick when on. All from the shortcut sheet.
  4. A marker flag on the ruler: Rename (focuses the marker's name in the side panel) and Remove marker Delete; both exist.

3Timeline · several clips selected

  1. Right-clicking a clip inside the selection acts on all of it; right-clicking outside it selects that clip alone first.
  2. Only what the editor does for a selection today: Leave gaps ⇧Delete (lift), Remove 3 clips Delete (ripple delete, the linked sound goes with each shot), Deselect Esc, and Re-render… when every picked clip is a V1 shot (the selection panel's button; greyed with "Shots on V1 only" when an audio clip is picked). Replace with another take stays in the list greyed with "One clip at a time" so the menu keeps its shape.

4Gallery · a take, several takes

  1. A take card: the side panel's actions for that take, in its order: Use in › (the take's offers, e.g. Animate · LTX Image to video, Edit · Qwen Image; a video adds Last frame in… / First frame in…), Edit (Media tools), Add to timeline (an audio take goes on an audio track), Reuse settings; then Star / Unstar, Rename, Full screen F, Save as element (images), Save as look, Save as pipeline (made takes), Export file; Delete last, with its card. Items the take can't have are left out, as the panel leaves them out. All exist.
  2. Several takes (Select several on): the selection bar's actions: Star, Add to timeline (in order), Save as element (greyed with its own reason, "An element takes 1 to 4 images", unless 1 to 4 images made from elements), Done (ends Select several), and Delete 3 takes with the bulk delete card.
  3. While Select several is on, right-clicking a card outside the picked ones picks it alone; with it off the menu is the one take's.

5Create · a take, a strip tile, a session

  1. The take on the stage: the stage's own buttons and the row under it: Full screen F, Compare, Explain run, Star / Starred; then Extend (a video take, its family's Extend), Add to timeline, Save as voice… (an audio take, where a workflow clones), Use in › (the Use in… popup's offers, Last / First frame in… for a video); Delete last with "Delete this take?". Each shows only when the stage shows it today. All exist.
  2. A strip tile: today right-click opens the tile's ⋯ menu with Delete alone; it becomes this menu. Show puts the tile on the stage (the click); the take's actions follow and act on that tile's take, so the tile need not be shown first. A run still going, or a failed one, has no menu (as now); a failed one keeps its ✕. A batch's run keeps none, as now.
  3. A session in the session menu (the title chip's ⌄): Open, Rename (in place) and Delete with its card, greyed with "A run is going: stop it first to delete" while one of its runs is going. The same items its row's buttons have today.

6Text field · our menu there too

  1. Every input and text area (prompts, names, notes, search, the chat box) gets our menu: Cut ⌘X, Copy ⌘C, Paste ⌘V, Select all ⌘A. Cut and Copy are greyed with "Select some text first" when nothing is selected; Cut and Paste are greyed in a read-only field. All four are new as menu items (the keys work today, from the browser).
  2. Insert @… only in a prompt that takes @ mentions (Create's prompt, a batch's prompt cells): it types @ at the caret and opens the @ menu the prompt already has. new as an item.
  3. Mac app: a misspelt word under the pointer puts the spelling suggestions first (up to three, bold), then Add to dictionary, a separator and the four edit items; Electron gives the word and its suggestions with the right-click. new.
  4. Browser: Cut and Copy write the clipboard straight away. The first Paste makes the browser ask ("wants to see text and images copied to the clipboard"), once per site; Allow pastes, Block greys Paste with its reason, and the ⌘V key keeps working either way. Firefox asks on every Paste with its own small Paste button; that is the browser's, not ours.
  5. Shift + right-click in a field still opens the browser's menu (Look up, Inspect, the browser's spelling).

7Create · an @ chip in a prompt

  1. A chip is the @handle the prompt draws over its text. Right-click on it opens the chip's menu; anywhere else in the prompt it is the text field's menu (frame 6).
  2. Edit @fox opens the element's edit form (the Elements popup's ✎, exists). Replace with › lists the elements as the @ menu does and swaps the handle new. Write as text turns it into @@fox, the literal the prompt already reads new. Remove from prompt deletes the handle text, back with ⌘Z like typing new; no card.
  3. An unknown handle (marked, "No element @owl"): New element @owl opens New element with the handle filled new (New element exists, the prefill does not).

8Graph · a node, the canvas, a wire

  1. Both graphs: Create's Graph view and a pipeline's graph. Right-click selects the node or wire first, as everywhere.
  2. A node (Graph view): Bypass / Bypassed where the node can pass through (the inspector's switch), Duplicate ⌘D new, Delete node (the Delete key, no card, back with ⌘Z). A step (Pipelines): Rename (the title's double-click), Open memory on a judge with memory, Duplicate new, Delete step. A read-only graph (an execution view, another user's) has only Open memory.
  3. The empty canvas: Add node… A opens Add node at the pointer (the double-click), Tidy layout (Graph view only), Undo ⌘Z, Redo ⇧⌘Z, greyed when there is nothing to undo or redo.
  4. A wire: the header names both ends; Add a node on it… opens Add node with the kinds that take this wire, as a wire dropped on the canvas does, and puts the node between new; Remove wire (Delete, no card, ⌘Z).

9Assistant chat · a message, a take

  1. An answer: Copy (the answer's Copy button), Retry where the chat shows it (after a broken answer; greyed with its reason elsewhere), Undo what it did when the answer has action lines with Undo (the same call). Your message: Copy alone new (there is no button for it today). Selected text in a message gets frame 6's menu, read-only.
  2. A take in the chat: Open (full screen, the take's Open), Play for a video or audio take, Use in › (its Use in… list). All exist.

10Models · a model card

  1. Everyone: Open (the click: the card's details on the right) and Licence (its licence text, the Licence per variant link).
  2. Admins, as the detail panel shows them today: Download to host… (opens the licence and Download card, greyed with its reason when nothing can be fetched), Cancel download in its place while one runs, Delete from host… last with its card "Delete LTX-2.5 · 22B from mac-studio?". An add-on row has the same Download… and Delete.

11Libraries · a LoRA, a voice, an element

  1. A LoRA: Add (the tile's click in Create's Add LoRA picker: onto the node's LoRA stack; left out on Models › LoRAs), Rename, Delete with "Delete this LoRA?" (in the picker, its inline "Delete Dusk grade? Takes made with it keep it."). A shared LoRA (admin): Delete from host… with "Delete Dusk grade from mac-studio?" alone.
  2. A voice: Play its sample, Use (the click), and for your own Rename and Delete (its ⋮ menu, Delete's inline "Delete Narrator? Takes made with it keep it."). A starter voice has Play and Use only.
  3. An element: Put @fox in the prompt (the tile's click), Edit, Delete with "Delete @fox? Takes made with it keep it.". All exist.

12Hub and System · a row in each list

  1. A row's menu is its ⋯ menu or its buttons, nothing more; the turn-off and delete items go last in red with the card each has today.
  2. Providers: Test, Edit, then Disable / Enable and Delete… ("Delete this provider?"). Plugins: Open in Providers or Add as provider (a model provider; greyed with the reason on others), Open Assistant, Remove… ("Remove Web search?"); a faded plugin has Remove only.
  3. Users: Roles…, Reset password…, Disable / Enable, no card as now (Enable undoes it). The root admin's row has no menu, as it has no buttons.
  4. Hosts: a host card: Unload all… and Evict all… with their cards; a resident component: Pin / Unpin and Unload… ("Unload ltx-2.5 · dit?"). API keys: Revoke… ("Revoke this key?"), and Copy prefix new; a revoked key has no menu.

13Magic · drawn on its own board

  1. Magic's menus are drawn in the app look on MagicBoard frame 10 (plan 39): a block of each kind (video, voice, music, sound, a storyboard frame), a lane header, the empty lane at a time, an asset, a transition point, a link mark, an effect badge, several blocks, a snapshot and a send. They use this shared menu and its rules (frame 0).
  2. The earlier sketch here is replaced: it had Open in Timeline on a block, but Magic is separate from the Timeline (plan 37 decision 9); the only bridge is Send to Timeline, which makes a new sequence, and a send's own menu opens that sequence.
