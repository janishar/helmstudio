Right-click menus

alpha.5 item 17 · owner 2026-11-26: "is it possible to have our own double click menu", "right click in mean", then "App-wide"

0The rules

  1. Ours on media and editing surfaces: Timeline lanes, ruler and track headers; Gallery take cards; Create's stage and strip and the session menu; later Magic's lanes. Everything else (prompts, names, notes, any input or text area, and selected text anywhere) keeps the browser's menu, so copy, paste, spelling and Inspect still work. Shift + right-click always shows the browser's menu, ours or not.
  2. One shared menu with the app's menu look (the .menu shell of the Create chip popups and Run on): a header naming what it acts on, items with an icon, the label and its shortcut key on the right, groups with separators, the danger item (Delete, Remove) last in red.
  3. Only real actions. Every item calls the action the page already has (inspector buttons, the shortcut list behind ?, the Gallery's take actions, Use in…). An item tagged new on this board has no action today; the rest exist. An item that can't run now is greyed with its reason on hover rather than hidden, the same rule as greyed fields elsewhere.
  4. Submenus only where a list needs one: Use in ›, Replace with another take ›, Move to track ›. They open on hover or → and close on ←.
  5. Opens at the pointer, kept on screen (flips left or up near an edge). Esc or a click outside closes it; ↑ ↓ move, Enter picks, typing a letter jumps to the item starting with it. Focus goes back to where it was.
  6. Keyboard: ⇧F10 or the context-menu key opens the menu of the focused item (a clip, a card, a tile), at its bottom-left corner, first item focused. Screen readers hear it as a menu (role menu, menuitem).
  7. Right-click selects first: on something not selected it selects that one alone, then opens; on a selection it acts on the whole selection (frame 3, frame 4). The existing ⋯ buttons stay and open the same menu.
  8. Items that act at a time (New shot, Add marker, Mark in) act at the pointer's time, not the playhead; the playhead does not move.

1Timeline · a clip

  1. A shot on V1: the clip inspector's actions, in its order. Generate from this clip first: the take's offers (Extend · LTX-2.5 Extend here; whatever the clip's workflows offer, as the inspector lists them), Redo this shot, Replace with another take › (its other takes, seed 42 / 44 / 45, the current one ticked), Use in › (Last frame in…, First frame in…, then the frame's offers), Re-render…. Then the edit keys: Split at playhead S, Mark clip as range X, Leave a gap ⇧Delete, and last Remove clip Delete (ripple). All exist today.
  2. An empty slot on V1 (a lifted shot) shows New shot here (or Try this shot again after a failed run) and Remove clip; a shot still running shows only its run's state and greys the rest with "The shot is still running".
  3. An audio clip: today's ⋯ menu (Make shot, Replace with another take, Use in…, Save as voice…, Remove clip), plus the inspector's Mute and the edit keys. Move to track › lists the other audio tracks; it is the drag between tracks the lanes already do (the move op with a track), so nothing new behind it; New audio track in it is + Audio track, then the move.
  4. A linked pair (a V1 shot and its A1 sound) acts together, as selecting does today; ⌥ + right-click picks the one clip, as ⌥ + click does.

2Timeline · a gap, a track, the ruler

  1. An empty gap on a track (or past the last clip): New shot (opens New shot docked, at the pointer's time instead of the playhead), New line (New line on that track), Add clips to A2 (the side panel's Add clips for the track), Add marker M. Close gap is new: no op closes a gap today (Delete ripples only when it removes a clip); greyed "Nothing after it to move" past the last clip. On V1 there are no gaps (shots butt), so the gap menu shows on audio tracks only.
  2. A track header: the track panel's own items: Mute (Muted, ticked, when on), Add clips to A2, New line on it, Add audio track (the lanes' + Audio track), and Remove track last (with its confirm when the track has clips). V1 and A1 headers show Mute only where the inspector has it, and Remove track greyed with "V1 holds the shots" / "A1 is V1's own sound".
  3. The ruler: Add marker M, Mark in I, Mark out O at the pointer's time, Clear range ⌥X (greyed with "No range set" when there is none), the zoom keys Zoom in ⌘=, Zoom out ⌘−, Fit ⇧Z, and the two toggles Snapping N and Hover scrub ⇧S with a tick when on. All from the shortcut sheet.
  4. A marker flag on the ruler: Rename (focuses the marker's name in the side panel) and Remove marker Delete; both exist.

3Timeline · several clips selected

  1. Right-clicking a clip inside the selection acts on all of it; right-clicking outside it selects that clip alone first.
  2. Only what the editor does for a selection today: Leave gaps ⇧Delete (lift), Remove 3 clips Delete (ripple delete, the linked sound goes with each shot), Deselect Esc. The one-clip actions stay in the list greyed with "One clip at a time" so the menu keeps its shape.

4Gallery · a take, several takes

  1. A take card: the side panel's actions for that take, in its order: Use in › (the take's offers, e.g. Animate · LTX Image to video, Edit · Qwen Image; a video adds Last frame in… / First frame in…), Edit (Media tools), Add to timeline (an audio take goes on an audio track), Reuse settings; then Star / Unstar, Rename, Full screen F, Save as element (images), Save as look, Save as pipeline (made takes), Export file; Delete last, with its card. Items the take can't have are left out, as the panel leaves them out. All exist.
  2. Several takes (Select several on): the selection bar's actions: Star, Add to timeline (in order), Save as element (greyed with its own reason, "An element takes 1 to 4 images", unless 1 to 4 images made from elements), Done (ends Select several), and Delete 3 takes with the bulk delete card.
  3. While Select several is on, right-clicking a card outside the picked ones picks it alone; with it off the menu is the one take's.

5Create · a take, a strip tile, a session

  1. The take on the stage: the stage's own buttons and the row under it: Full screen F, Compare, Explain run, Star / Starred; then Extend (a video take, its family's Extend), Add to timeline, Save as voice… (an audio take, where a workflow clones), Use in › (the Use in… popup's offers, Last / First frame in… for a video); Delete last with "Delete this take?". Each shows only when the stage shows it today. All exist.
  2. A strip tile: today right-click opens the tile's ⋯ menu with Delete alone; it becomes this menu. Show puts the tile on the stage (the click); the take's actions follow and act on that tile's take, so the tile need not be shown first. A run still going, or a failed one, has no menu (as now); a failed one keeps its ✕. A batch's run keeps none, as now.
  3. A session in the session menu (the title chip's ⌄): Open, Rename (in place) and Delete with its card, greyed with "Stop its runs first" while one of its runs is going. The same items its row's buttons have today.

6Magic · a block, a join, an empty spot later, with Magic

  1. Magic is a concept (docs/mock/Magic.dc.html, plan 37); these menus come with it, not in alpha.5. They use the concept's own buttons.
  2. A block: Open block, Run this block, Run up to here, Compare (its takes), Unpin / Pin the take, Open in Timeline; Delete block is new (the concept has no delete yet).
  3. A join (the diamond between two blocks): the join kind as a radio list, Cut, Dissolve 0.5 s, Fade 1 s, then Unlink (the link between the shots). All from the concept's join popover. Drawn flipped: near the right edge the menu opens to the left of the pointer.
  4. An empty lane spot: Add… opens the Add dialog at that time and lane (the click does that today); Add and run… is new as a shortcut: the same dialog with Add and run as its main button.
