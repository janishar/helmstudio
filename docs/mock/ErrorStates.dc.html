helmstudio · Error states (proposed)

What the web app shows when the studio or a runner is not there, drawn in place on Create, Magic and the Timeline. Each frame has a note: when it shows, its words, what each button does, and when it clears. The Mac app’s own states are on the Mac app board, section “Error states (proposed)”. From the audit of 2026-11-27; boards only, nothing built.

a · Studio isn’t answering

One banner for the whole app, on every page, instead of the raw “the API is unreachable”, “Failed to fetch” and the silent poll catches. It sits at the top of the page column and pushes the page down, so nothing is hidden.

b · No runner for this model

Generate knows before you press it. The plan call already returns a reason (POST /v1/studio/runs/plan, “no live host for env mlx”); the web uses it instead of discarding it. The wrong “runs wait until one is” line goes.

c · Runner lost mid-run

The studio already requeues a run once when its runner stops (attempt 2). Today the web wipes the progress and shows a bare “Queued”, then a raw error in mono. Now it says what happened, and the failure is in plain words with the raw text one click away.

g · Status in the shell

One small status tile under the rail, the same words as the Mac menu bar. It shows only when something is down; when all is well there is nothing to see.
