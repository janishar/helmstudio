## 8. UI — fresh design

This section owns screens and widgets. Behaviour behind them is owned
elsewhere and only pointed to.

### 8.1 Navigation

Five items in the left rail.

| Item | What it is |
|---|---|
| **Create** | One image or one clip at a time. The Studio of a single template, chosen with the Image / Video switch and the model chip. |
| **Pipelines** | Automation (section 7.2): every batch, running or finished, with its run view (section 8.3), and saved pipelines with their graph. |
| **Gallery** | Every take, with lineage, search and the take actions (section 9.1). |
| **Timeline** | Sequences: arrange takes, direct new shots, export (section 15). |
| **Models** | For everyone: each model with its presence per host, and the LoRA library, where users upload their own. Admins also download and delete weights (sections 9.2, 6.4). |

Below the menu: the signed-in user's menu (account, API keys for `helm`, sign
out). Admins also get **Hosts** (runners, memory, resident components, pins,
the after-run setting) and **Users** (add accounts, roles, reset password,
disable; section 17.3) as tabs of one **Admin** screen in the dock. Sign-in is the only
screen before an account is known.

Elements and looks have no menu item: they are created, edited and browsed in
their pickers, which open from any composer.

```
│G │ │                                                    │ │ ▸ Canvas   │
│T │ │             STAGE  (output / live preview)         │ │ ▸ Quality  │
│M │ │                                                    │ │ ▸ LoRA     │

│  │ ╰────────────────────────────────────────────────────╯ │            │
└──┴────────────────────────────────────────────────────────┴────────────┘
```

- **Top bar**: session switcher (current project, recent, new); a read-only
  badge with the open template and its mode; Studio | Graph; memory chip.
- **Composer** (floating, bottom):
  - Image / Video switch — a filter on which templates the model chip offers;
    switching follows the session rule in section 4.
  - Quick chips from `studio.quick`: parameters, and library groups shown as
    tiles that open the visual picker.
  - **Run on** right after the model chip (API 1.35, docs/mock/RunOn.dc.html): Auto (the dispatcher's own
    placement, the default) or one connected host, named by its device (Mac, NVIDIA; the host name when two share
    one). A host that cannot take the run is greyed with why; a run set to a host never moves to another one.
  - Prompt with `@` element chips and history.
  - Seed count stepper with "List…" to start a batch, and **Generate** (reads "Add to queue" while a run is
    active) showing estimated time and peak memory.
- **Empty state**: before the first run the stage is replaced by a neutral
  "What will you make?" headline with the composer centred.
- **Stage**: the output or the live preview, a scrubber over saved step
  previews, A/B wipe and seed-grid compare. Text outputs such as an enhanced
  prompt show as a card under the stage with a diff and "use as prompt".
- **Takes filmstrip**: this session's takes for the open template, each with
  the take actions of section 9.1.
- **Run strip**: built from the graph's actual nodes with real per-node
  progress.
- **Inspector** (right): preset chips and the sections from `studio.inspector`.
- **Memory chip**: used and total for the host, and whether it is busy
  (section 6.2).
- **Explain drawer**: the resolved run — parameters after defaults, preset and
  library items, what each element or look added, model, precision, LoRAs,
  planned memory per stage — and "copy as `helm run`".
- **Studio ⇄ Graph** (⌘\\): a view of the open workflow. A pipeline's graph
  shows every node of section 16.2 and its edges, with each loop's cap. In Graph view nodes are cards with the same widgets, the stage
  docks as picture-in-picture, the inspector follows the selected node (its
  parameters, what re-runs it, its planned peak), incompatible ports dim while
  dragging.
- **Errors** appear on the node that failed, with the known hint and a fix
  action. Logs are a drawer, never a primary surface.
- **⌘K** palette: open template or pipeline, add node, switch session.
  ⌘↵ generate, ⇧⌘↵ generate the seed count.

### 8.3 Batch run view (Pipelines)

- **Header**: done / failed / waiting for a pick / not run; started, finished
  and wall time; model loads; what is still loaded.
- **Table**: one row per input. A column for the input (thumbnail or the start
  of the prompt, plus CSV or grid values), then one cell per node the row reached, loop
  attempts stacked in the same cell: status, a
  thumbnail of the take, seed, time taken, measured peak memory. A failed cell
  shows the error hint and Retry. A judged cell shows the verdict (picked 1 of
  4, retried 1 of 2, gave up → review) and the first failed criterion; opening
  it shows every attempt side by side with the reasons.
- **Actions**: Retry failed, Pick (opens the review grid), Pause, Cancel
  remaining, Open collection, Run again. Any row opens in the execution view
  (section 16.8).
- **Run settings**: on failure, and notify when finished.

### 8.4 Shared widgets

One implementation each, used by the inspector, the composer, graph nodes and
the timeline's shot composer.

- **Canvas solver**: aspect + megapixels, snapped to the family grid, with readout.
- **Media viewer** (decided 2026-11-14): wherever a take is shown large (the
  Create stage, the Gallery preview, a timeline clip, a pipeline pick) it has
  a Full screen button; video and audio also have Play. Full screen fills the
  display, Esc closes, the arrow keys step through the takes of the list it
  was opened from, and video plays with the native controls.
- **Duration slider** on the family's frame grid, with auto length where the
  model predicts it.
- **Seed** with dice.
- **Rows editor**: reorder, per-item fields; used for references, keyframes,
  prompt beats and the LoRA stack.
- **Visual picker**: a thumbnail grid for models, LoRAs, elements and looks.
  Items that do not fit the current family are greyed out with the reason. A
  LoRA's thumbnail is the first take made with it.
- **Gallery picker**: the one way to choose media (section 9.1).
- **Toggles** state their memory or time cost.

### 8.5 Visual language

Our own look; Higgsfield was a reference for energy, not a template.

- **Themes**: seven, chosen in the Settings menu at the foot of the dock and
  remembered per user. **Forest ink** is the default (deep green ground, leaf and persimmon
  accents). The others: Deep ocean, Aubergine dusk, Espresso, Oxblood, Indigo
  night, and Parchment (light). None is neutral grey or black. Every colour in the UI is
  a theme variable, so a theme is one block of values.
- **Layers are tonal, not boxed.** Surfaces step up in tones of the ground;
  hairline borders are gone. The menu is a floating dock and the inspector a
  floating panel, each separated from the ground by space and shadow rather
  than a line. A faint warm light falls from the top left.
- **Shapes are soft and uneven**: large radii with one tighter corner
  (28 / 28 / 28 / 12 px), pills for small controls.
- **Depth**: a top highlight edge plus a long soft drop shadow. Buttons are
  bevelled. The primary action is a raised, glossy key in the family accent.
- **3D icon tiles**: each menu item is a glossy gradient tile with its own hue
  (Create violet, Pipelines blue, Gallery coral, Timeline amber, Models teal);
  inactive tiles are muted, the active one is ringed.
- **Accents**: each theme has two, one for image work and one for video;
  wires keep their own colours (sky, lilac, amber, rose) in every theme.
- **Type**: Inter for text, Bricolage Grotesque for titles and the primary
  action, sentence case; JetBrains Mono for numbers. 14 px base.
- **Controls**: filled pills, settings as label-over-value tiles, spring
  motion, Lucide glyphs inside the icon tiles.
- **Few words on screen.** The surface shows values and state. Explanations
  ("why tiled decode was chosen", "what a look adds") sit behind a small info
  button beside the heading; only costs that change a decision (memory, time)
  stay inline.
- **Nothing touches.** Panels, cards, clips and graph nodes keep a visible gap
  from each other and from their container's edge (at least 8 px between
  controls, 16 px between cards, 24 px between graph nodes); graphs are laid
  out to fit their panel rather than run under its border.
- Light theme designed, not inverted.

### 8.6 Stack

The reference's web stack: Next.js (App Router) with React 19 and TypeScript,
Tailwind 4 with CSS-variable tokens, shadcn/ui, Lucide (versions in
section 18). The web service is a
backend-for-frontend (section 17.3). API types are generated from
`contracts/openapi.yaml`; the UI follows one event stream per session (SSE) and
treats events as hints to refetch. `@xyflow/react` with elkjs for the graph
views (MIT, the best-maintained node canvas as of Nov 2026). Forms render the
resolved schema the API returns.

### 8.7 Mock

**The mock is the specification** (decided 2026-11-14): every screen is built
to match its board in `docs/mock/` part by part — layout, spacing, components
and styling. A control whose backend does not exist yet is left out, not
redesigned. A change to a built screen that differs from the mock changes the
mock too.

https://claude.ai/artifact/M6HPauDMh4q6R2dMbCe8zR — Create (Qwen Image, LTX
text to video, empty state), Graph, Pipelines (review pick with the memory
panel; graph and run table of an unattended batch with a judge and memory, and
the execution view of one row), Gallery, Timeline, Admin (users), and the public landing page. Not mocked:
Models, the pipelines list, the Explain drawer, compare, sign-in, the user
menu and Hosts.
